# MCP-инструменты

Каждая операция Tracker API из встроенной спецификации — отдельный MCP-инструмент. Спецификация собрана из [справочника Tracker API](https://yandex.ru/support/tracker/ru/api/about-api) и покрывает все его методы: 195 операций в 13 наборах. Имя инструмента — `operationId` операции в snake_case (`get_issue`, `search_issues`, `new_transition`), описание — из справочника и заканчивается ссылкой на его страницу. Кроме операций всегда доступны `api_search` и `api_request`.

Какие инструменты видит агент, задают уровень доступа (`--allow-write`, `--allow-destructive`) и наборы (`--toolsets`) сервера. Со значениями по умолчанию — только чтение и четыре набора — это 58 инструментов операций; с `--allow-write` — 100, с `--allow-destructive` — 116.

## Уровни доступа

По умолчанию сервер работает только на чтение. Инструменты выше разрешённого уровня не регистрируются: агент их не видит, а вызов по имени возвращает ошибку с флагом, который их включает.

| Уровень | Как включить | Инструменты |
| --- | --- | --- |
| read-only | по умолчанию | только чтение, в том числе поиск задач (`POST /v3/issues/_search`) |
| write | `--allow-write` | плюс создание и изменение: задачи, комментарии, переходы, связи, учёт времени |
| destructive | `--allow-destructive` | плюс удаление и необратимые изменения |

У каждого инструмента есть аннотации MCP: `readOnlyHint`, `destructiveHint`, `idempotentHint` (для изменяющих: `PUT` и `DELETE` идемпотентны, `POST` и `PATCH` — нет), `openWorldHint` и `title`.

Флаги командной строки важнее настроек профиля ([`serve`](cli.md#уровни-доступа-и-наборы)). Уровень доступа сервера не расширяет права токена: Tracker всё равно проверяет права пользователя и [права OAuth-приложения](oauth.md#права-приложения).

## Наборы инструментов

Набор — раздел справочника Tracker API. Без `--toolsets` и без настройки профиля включены `issues`, `queues`, `boards` и `users`: этого хватает для работы с задачами, а со всеми наборами список инструментов в контексте агента в полтора–два раза больше. `--toolsets all` включает все наборы.

| Набор | Раздел справочника | По умолчанию |
| --- | --- | --- |
| `issues` | Задачи: комментарии, связи, чеклисты, файлы, учёт времени, поля | да |
| `queues` | Очереди: локальные поля, версии, компоненты, триггеры, автодействия | да |
| `boards` | Доски и спринты | да |
| `users` | Пользователи организации | да |
| `macros` | Макросы очередей | |
| `entities` | Проекты, портфели и цели | |
| `projects` | Проекты (старый API) | |
| `dashboards` | Дашборды и виджеты | |
| `filters` | Сохранённые фильтры задач | |
| `bulkchange` | Массовые операции | |
| `import` | Импорт задач из других систем | |
| `admin` | Типы задач, приоритеты, резолюции и статусы | |
| `gaps` | Отсутствия сотрудников | |

Неизвестный набор — ошибка запуска со списком допустимых.

## Частые задачи

| Задача | Инструменты | Уровень |
| --- | --- | --- |
| Найти задачи по фильтру или на языке запросов | `search_issues` (`body`: `filter`, `query`, `keys` или `queue`) | чтение |
| Посчитать задачи | `count_issues` (`body`: `filter` или `query`) | чтение |
| Прочитать задачу, комментарии, переходы, связи, историю | `get_issue`, `get_comments`, `get_transitions`, `issues_get_links`, `get_changelog` | чтение |
| Создать и изменить задачу | `create_issue`, `patch_issue` | запись |
| Прокомментировать | `issues_add_comment` | запись |
| Перевести по статусу с комментарием и резолюцией | `get_transitions`, затем `new_transition` (`body`: `comment`, `resolution` и поля экрана перехода) | запись |
| Приложить файл к задаче | `post_attachment` | запись |
| Приложить файл к комментарию или описанию | `temp_attachment`, затем `attachmentIds` в `body` у `issues_add_comment`, `create_issue` или `patch_issue` | запись |
| Связать задачи | `link_issue` или поле `links` в `body` у `create_issue` | запись |
| Создать очередь, доску, спринт | `create_queue`, `post_board`, `post_sprint` | запись |
| Удалить комментарий, связь, файл | `issues_delete_comment`, `delete_link_issue`, `issues_delete_attachment` | удаление |

Если нужной операции нет среди зарегистрированных, агент находит её через `api_search`: в ответе сказано, какой флаг или набор её включает, а вызвать её в пределах уровня доступа можно через `api_request`.

## Аргументы и ответы

- Параметры пути и строки запроса — аргументы с именами из API (`issueId`, `queueId`, `perPage`); массив в строке запроса передаётся повторением ключа. JSON-тело запроса — аргумент `body`. Неизвестные аргументы и пропущенные обязательные — ошибка до отправки запроса.
- Результат — JSON-ответ Tracker. Если в ответе есть заголовки постраничной выдачи (`X-Total-Pages`, `X-Total-Count`, `X-Scroll-Id`, `Link`), ответ оборачивается: `{"result": <ответ>, "pagination": {"total_pages", "total_count", "scroll_id", "links"}}`.
- Ошибки Tracker (`4xx`, `5xx`) возвращаются агенту как ошибка инструмента (`isError: true`) с кодом, подсказкой и сообщениями Tracker; сервер продолжает работать.
- Значения, похожие на учётные данные, заменяются на `[redacted]` во всех ответах, в том числе в ошибках; к результату добавляется пометка, что и сколько скрыто. Подробности — в разделе [Учётные данные в ответах](security.md#учётные-данные-в-ответах).
- Описание каждого инструмента заканчивается ссылкой на страницу справочника.

## api_search и api_request

Два инструмента регистрируются всегда, независимо от `--toolsets`:

- `api_search` ищет по всем операциям спецификации, в том числе выключенным: по имени инструмента, `operationId`, описанию, пути и разделу справочника. Запрос можно писать по-английски и по-русски: русские слова сравниваются по основе и переводятся в имена из API («доска» находит операции досок `/v3/boards…`, «учёт времени» — операции `worklog`). В каждом результате — имя инструмента, метод, путь, уровень доступа, набор, обязательные параметры, ссылка на справочник, зарегистрирован ли инструмент и, если нет, каким флагом его включить (`--allow-write`, `--allow-destructive`, `--toolsets <набор>`). Аргумент `tool_name` возвращает полную схему аргументов одной операции; `toolset` ограничивает поиск набором; `limit` — число результатов (по умолчанию 20, не больше 100). В API инструмент не обращается и всегда только читает.
- `api_request` отправляет запрос к любому пути Tracker API: `method`, `path` (с версией: `/v3/…` или `/v2/…` для методов, которые есть только там), `query` (объект; массив передаётся повторением ключа), `body` (JSON) и `save_to` для скачивания файлов. Заголовки задать нельзя: токен и организацию добавляет сервер. Полные URL, `?`, `#`, `..` и пути без версии отклоняются.

Уровень доступа `api_request` определяется по спецификации: запрос сопоставляется с шаблонами путей операций (литеральные сегменты без учёта регистра и после percent-раскодирования, `/v2/` и `/v3/` взаимозаменяемы), и действует уровень совпавшей операции — при нескольких совпадениях максимальный. Поэтому поиск и подсчёт через `POST` (`/v3/issues/_search`, `/v3/issues/_count` и другие операции чтения) работают на сервере только для чтения. Путь, которого нет в спецификации, оценивается по методу: `GET` — чтение, `DELETE` — удаление, остальные — запись. Запрос выше уровня сервера не отправляется: агент получает ошибку с флагом, который нужен.

Аннотации `api_request` соответствуют уровню сервера: `readOnlyHint` в режиме чтения, `destructiveHint` с `--allow-destructive`. `save_to` принимается только для операций, которые возвращают файл (содержимое вложений, миниатюры): JSON-ответ в файл не сохраняется, он возвращается в результате с теми же заменами учётных данных.

## Постраничная выдача

Заголовки постраничной выдачи Tracker переносятся в поле `pagination` ответа:

- **Страницы** — `page` и `perPage` (по умолчанию 50); в `pagination` — `total_pages` и `total_count`.
- **Относительная выдача** — `perPage` и `id`; ссылка на следующую страницу — в `pagination.links` (`rel="next"`). Поиск задач с `body: {"queue": …}` поддерживает только её.
- **Прокрутка** больших выборок в `search_issues`: первый вызов с `scrollType` (`sorted` или `unsorted`), `perScroll` (до 1000) и необязательным `scrollTTLMillis`, следующие — с тем же `body` и `scrollId` из `pagination.scroll_id`, пока он не пропадёт. С `keys` и `queue` прокрутка не работает: используйте `filter` или `query`.

Ответ больше `--max-response-bytes` (256 КиБ по умолчанию) не обрезается, а возвращается ошибкой с подсказкой сузить запрос: запросите только нужные поля (`fields`), уменьшите `perPage` или уточните фильтр.

Подробности о пагинации в разных методах — в [описании спецификации](../crates/tracker-api/spec/README.md#постраничная-выдача).

## Локальные файлы

Инструменты загрузки (`post_attachment`, `temp_attachment`, `import_attachments`) принимают в аргументе `file` путь к файлу, а инструменты, которые возвращают файл (`issues_get_attachment`, `get_attachment_preview`, `api_request` для таких операций), сохраняют его по пути из `save_to`. Пути должны быть внутри разрешённых каталогов: рабочего каталога сервера, системного временного каталога и каталогов из `--allow-path` ([подробнее](security.md#локальные-файлы)). В [HTTP-режиме](http.md#отличия-от-stdio) эти инструменты не регистрируются.

## Инструкции сервера

При подключении сервер передаёт агенту инструкции: уровень доступа и включённые наборы, как найти выключенную операцию, как работать с постраничной выдачей и большими ответами, какие каталоги разрешены для файлов, что токен никогда не передаётся в аргументах и не запрашивается в чате и что делать при `401`. Отдельно сказано не переносить персональные данные из ответов в логи, коммиты и код без просьбы пользователя.
