# MCP-инструменты

Каждая операция Tracker API из встроенной спецификации — отдельный MCP-инструмент. Спецификация собрана из [справочника Tracker API](https://yandex.ru/support/tracker/ru/api/about-api) и покрывает все его методы: 195 операций в 13 наборах. Имя инструмента — `operationId` операции в snake_case (`get_issue`, `search_issues`, `new_transition`), описание — из справочника и заканчивается ссылкой на его страницу. Кроме операций всегда доступны `api_search` и `api_request`.

Какие инструменты видит агент, задают уровень доступа профиля и наборы (`--toolsets`) сервера. Со значениями по умолчанию — только чтение и четыре набора — это 58 инструментов операций; с уровнем записи — 100, с уровнем удаления — 116.

## Уровни доступа

По умолчанию сервер работает только на чтение. Инструменты выше разрешённого уровня не регистрируются: агент их не видит, а вызов по имени возвращает ошибку с подсказкой, как поднять уровень. Уровень — настройка профиля: его меняют `tracker-mcp ui` или `connect --allow-write`/`--allow-destructive`, на macOS — с одобрением через Touch ID или пароль ([Безопасность](security.md#уровни-доступа)). В [HTTP-режиме](http.md#права-доступа) уровень задают флаги `serve --http`.

| Уровень | В профиле | Инструменты |
| --- | --- | --- |
| read-only | по умолчанию | только чтение, в том числе поиск задач (`POST /v3/issues/_search`) |
| write | `allow_write = true` | плюс создание и изменение: задачи, комментарии, переходы, связи, учёт времени |
| destructive | `allow_destructive = true` (включает запись) | плюс удаление и необратимые изменения |

У каждого инструмента есть аннотации MCP: `readOnlyHint`, `destructiveHint`, `idempotentHint` (для изменяющих: `PUT` и `DELETE` идемпотентны, `POST` и `PATCH` — нет), `openWorldHint` и `title`.

Флаги `serve` права профиля только сужают ([`serve`](cli.md#уровни-доступа-и-наборы)). Уровень доступа сервера не расширяет права токена: Tracker всё равно проверяет права пользователя и [права OAuth-приложения](oauth.md#права-приложения).

### Динамические наборы

Клиенты, которые не откладывают загрузку инструментов, кладут описания всех зарегистрированных инструментов в контекст модели сразу. С флагом `serve --dynamic-toolsets` (или `connect --dynamic-toolsets`, тогда настройка сохраняется в профиле) сервер при запуске регистрирует только:

- `api_search` и `api_request` — как обычно;
- [пользовательские инструменты](#пользовательские-инструменты) из `tools.toml` — их настроил пользователь, поэтому они регистрируются сразу и не входят ни в один набор;
- `list_toolsets` — наборы с разделом справочника, инструментами, доступными на текущем уровне, примерами имён, числом операций выше уровня доступа (`above_access_level`) и признаком `enabled`;
- `enable_toolset` — включить набор (аргумент `toolset`, можно несколько через запятую или `all`). Ответ перечисляет добавленные инструменты;
- `disable_toolset` — выключить набор, чтобы снова сократить список.

`--toolsets` (или наборы профиля) вместе с `--dynamic-toolsets` задают наборы, включённые при запуске; без них при запуске не включено ни одного набора. После `enable_toolset` и `disable_toolset` сервер отправляет клиенту `notifications/tools/list_changed` (в инициализации объявлена возможность `tools.listChanged`): в сессии с `initialize` — сразу после вызова, в протоколе MCP 2026-07-28 — по подписке `subscriptions/listen`. Клиент перечитывает `tools/list` и видит новые инструменты.

Уровень доступа действует как обычно: `enable_toolset` не регистрирует инструменты выше разрешённого уровня. Включённые инструменты — те же, что без `--dynamic-toolsets`, и тоже принимают [фильтр `jq`](#фильтр-ответа-jq). Сами инструменты управления наборами — уровня чтения: они меняют только список инструментов сервера, а не данные Tracker, и к API не обращаются. Если клиент не перечитывает список инструментов, агент может вызвать ту же операцию через `api_request` (метод и путь подскажет `api_search`).

Динамические наборы работают только в stdio: HTTP-сервер ([HTTP-режим](http.md)) не хранит сессий, поэтому `--dynamic-toolsets` вместе с `--http` — ошибка запуска. Состояние наборов принадлежит сессии: после перезапуска сервера включены снова только наборы из `--toolsets` или профиля.

## Частые задачи

| Задача | Инструменты | Уровень |
| --- | --- | --- |
| Найти задачи по фильтру или на языке запросов | `search_issues` (`body`: `filter`, `query`, `keys` или `queue`) | чтение |
| Посчитать задачи | `count_issues` (`body`: `filter` или `query`) | чтение |
| Прочитать задачу, комментарии, переходы, связи, историю | `get_issue`, `get_comments`, `get_transitions`, `issues_get_links`, `get_changelog` | чтение |
| Создать и изменить задачу | `create_issue`, `patch_issue` | запись |
| Прокомментировать | `issues_add_comment` | запись |
| Перевести по статусу с комментарием и резолюцией | `get_transitions`, затем `new_transition` (`body`: `comment`, `resolution` и поля экрана перехода) | запись |
| Приложить файл к задаче | `post_attachment` | запись |
| Приложить файл к комментарию или описанию | `temp_attachment`, затем `attachmentIds` в `body` у `issues_add_comment`, `create_issue` или `patch_issue` | запись |
| Связать задачи | `link_issue` или поле `links` в `body` у `create_issue` | запись |
| Создать очередь, доску, спринт | `create_queue`, `post_board`, `post_sprint` | запись |
| Удалить комментарий, связь, файл | `issues_delete_comment`, `delete_link_issue`, `issues_delete_attachment` | удаление |

Если нужной операции нет среди зарегистрированных, агент находит её через `api_search`: в ответе сказано, какой флаг или набор её включает, а вызвать её в пределах уровня доступа можно через `api_request`.

## Аргументы и ответы

- Параметры пути и строки запроса — аргументы с именами из API (`issueId`, `queueId`, `perPage`); массив в строке запроса передаётся повторением ключа. JSON-тело запроса — аргумент `body`. Неизвестные аргументы и пропущенные обязательные — ошибка до отправки запроса.
- Результат — JSON-ответ Tracker. Если в ответе есть заголовки постраничной выдачи (`X-Total-Pages`, `X-Total-Count`, `X-Scroll-Id`, `Link`), ответ оборачивается: `{"result": <ответ>, "pagination": {"total_pages", "total_count", "scroll_id", "links"}}`.
- Ошибки Tracker (`4xx`, `5xx`) возвращаются агенту как ошибка инструмента (`isError: true`) с кодом, подсказкой и сообщениями Tracker; сервер продолжает работать.
- Значения, похожие на учётные данные, заменяются на `[redacted]` во всех ответах, в том числе в ошибках; к результату добавляется пометка, что и сколько скрыто. Подробности — в разделе [Учётные данные в ответах](security.md#учётные-данные-в-ответах).
- Описание каждого инструмента заканчивается ссылкой на страницу справочника.

## api_search и api_request

Два инструмента регистрируются всегда, независимо от `--toolsets` и `--dynamic-toolsets`:

- `api_search` ищет по всем операциям спецификации, в том числе выключенным: по имени инструмента, `operationId`, описанию, пути и разделу справочника. Запрос можно писать по-английски и по-русски: русские слова сравниваются по основе и переводятся в имена из API («доска» находит операции досок `/v3/boards…`, «учёт времени» — операции `worklog`). В каждом результате — имя инструмента, метод, путь, уровень доступа, набор, обязательные параметры, ссылка на справочник, зарегистрирован ли инструмент и, если нет, что его включает (`enable_with`: уровень доступа профиля и `--toolsets <набор>`; в HTTP-режиме — флаги `--allow-write`, `--allow-destructive`). Аргумент `tool_name` возвращает полную схему аргументов одной операции; `toolset` ограничивает поиск набором; `limit` — число результатов (по умолчанию 20, не больше 100). В API инструмент не обращается и всегда только читает. С `--dynamic-toolsets` для операции из выключенного набора он подсказывает вызов `enable_toolset`.
- `api_request` отправляет запрос к любому пути Tracker API: `method`, `path` (с версией: `/v3/…` или `/v2/…` для методов, которые есть только там), `query` (объект; массив передаётся повторением ключа), `body` (JSON), `jq` ([фильтр ответа](#фильтр-ответа-jq)) и `save_to` для скачивания файлов. Заголовки задать нельзя: токен и организацию добавляет сервер. Полные URL, `?`, `#`, `..` и пути без версии отклоняются.

Уровень доступа `api_request` определяется по спецификации: запрос сопоставляется с шаблонами путей операций (литеральные сегменты без учёта регистра и после percent-раскодирования, `/v2/` и `/v3/` взаимозаменяемы), и действует уровень совпавшей операции — при нескольких совпадениях максимальный. Поэтому поиск и подсчёт через `POST` (`/v3/issues/_search`, `/v3/issues/_count` и другие операции чтения) работают на сервере только для чтения. Путь, которого нет в спецификации, оценивается по методу: `GET` — чтение, `DELETE` — удаление, остальные — запись. Запрос выше уровня сервера не отправляется: агент получает ошибку с подсказкой, как поднять уровень.

Аннотации `api_request` соответствуют уровню сервера: `readOnlyHint` в режиме чтения, `destructiveHint` на уровне удаления. `save_to` принимается только для операций, которые возвращают файл (содержимое вложений, миниатюры): JSON-ответ в файл не сохраняется, он возвращается в результате с теми же заменами учётных данных.

## Постраничная выдача

Заголовки постраничной выдачи Tracker переносятся в поле `pagination` ответа:

- **Страницы** — `page` и `perPage` (по умолчанию 50); в `pagination` — `total_pages` и `total_count`.
- **Относительная выдача** — `perPage` и `id`; ссылка на следующую страницу — в `pagination.links` (`rel="next"`). Поиск задач с `body: {"queue": …}` поддерживает только её.
- **Прокрутка** больших выборок в `search_issues`: первый вызов с `scrollType` (`sorted` или `unsorted`), `perScroll` (до 1000) и необязательным `scrollTTLMillis`, следующие — с тем же `body` и `scrollId` из `pagination.scroll_id`, пока он не пропадёт. С `keys` и `queue` прокрутка не работает: используйте `filter` или `query`.

Ответ больше `--max-response-bytes` (256 КиБ по умолчанию) не обрезается, а возвращается ошибкой с подсказкой сузить запрос: запросите только нужные поля (`fields`), уменьшите `perPage`, уточните фильтр или оставьте нужное [фильтром `jq`](#фильтр-ответа-jq).

Подробности о пагинации в разных методах — в [описании спецификации](../crates/tracker-api/spec/README.md#постраничная-выдача).

## Фильтр ответа jq

Ответы Tracker бывают большими: список задач с описаниями быстро занимает контекст агента. Инструменты операций, `api_request` и [пользовательские инструменты](#пользовательские-инструменты) принимают необязательный аргумент `jq` — фильтр на языке [jq](https://jqlang.org/manual/) (диалект [jaq](https://github.com/01mf02/jaq)), который применяется к JSON-ответу до возврата агенту:

```json
{
  "body": {"query": "Queue: TEST Resolution: empty()"},
  "jq": ".[] | {key, summary}"
}
```

- **Порядок обработки:** замена учётных данных на `[redacted]` → фильтр → лимит размера. Фильтр получает уже очищенный ответ, поэтому никакой фильтр (например, `.. | strings`) не раскрывает скрытые значения. Лимит `--max-response-bytes` применяется к результату фильтра; исходный ответ для фильтра читается до 16 МиБ. Результат больше лимита — ошибка с пометкой, что сам запрос выполнен.
- **Постраничная выдача.** Если ответ обёрнут в `{"result": …, "pagination": …}`, фильтр применяется к телу ответа Tracker, а `pagination` остаётся рядом: `{"result": <результат фильтра>, "pagination": {…}}`. Поэтому `.[] | {key, summary}` для `search_issues` работает одинаково с заголовками постраничной выдачи и без них.
- **Результат:** ровно один результат фильтра возвращается как есть; несколько — JSON-массивом (`.[] | {key, summary}` → `[{…}, {…}]`); ни одного — `[]`.
- **Ошибки.** Синтаксис и имена функций проверяются до запроса к API: неверный фильтр — ошибка `isError: true`, а запрос не отправляется. Если фильтр упал при выполнении, ошибка сообщает, что сам запрос к API выполнен: запрос, изменяющий данные, повторять не нужно.
- **Ответ не в JSON** (текст, пустое тело) возвращается без фильтра, с пояснением. У инструментов, которые сохраняют файл (`save_to`), аргумента `jq` нет; `api_request` с `jq` и `save_to` одновременно — ошибка.
- **Ограничения фильтра.** Длина — до 4096 байт. Недоступны окружение процесса (`env`, `$ENV`), входные потоки (`input`, `inputs`) и модули (`import`, `include`); `debug` и `stderr` ничего не выводят, `halt` — ошибка. Фильтр выполняется в отдельном процессе с пустым окружением и прерывается через 10 секунд: зацикленный или бесконечно рекурсивный фильтр возвращает ошибку и не влияет на сервер.

## Пользовательские инструменты

Частые запросы можно оформить именованными инструментами, чтобы агент не собирал их каждый раз заново: например, «мои открытые задачи». Пользовательский инструмент вызывает одну операцию Tracker API с фиксированными аргументами и необязательным фильтром `jq`. Инструменты описываются в TOML:

- `tools.toml` в каталоге конфигурации рядом с `profiles.toml` (`~/.config/tracker-mcp/tools.toml`; каталог можно переопределить переменной `TRACKER_MCP_CONFIG_DIR`, на Linux учитывается `XDG_CONFIG_HOME`, в Windows — `%APPDATA%`) — читается при каждом запуске `serve`, если файл есть;
- другие файлы — только явно, флагом `serve --tools-file <путь>` (можно повторять). Файл из репозитория проекта — недоверенный ввод, поэтому клонирование репозитория само по себе инструментов не добавляет.

В [HTTP-режиме](http.md) читаются только файлы из `--tools-file` — на машине сервера при запуске; инструмент вызывается с токеном агента из запроса. Инструменты над операциями с локальными файлами там не регистрируются.

```toml
[[tools]]
name = "my_open_issues"
description = "Open issues assigned to me: key and summary only"
operation = "search_issues"
jq = ".[] | {key, summary}"

[tools.args]
perPage = 50
body = { query = "Assignee: me() Resolution: empty()" }

[[tools]]
name = "comment_release_issue"
description = "Add a comment to the release issue TEST-1"
operation = "issues_add_comment"
args = { issueId = "TEST-1" }
```

| Поле | Назначение |
| --- | --- |
| `name` | Имя инструмента: строчные латинские буквы, цифры и `_`, начинается с буквы, до 64 символов. |
| `description` | Описание для агента (обязательно). Сервер дополняет его операцией, фиксированными аргументами и ссылкой на справочник. |
| `operation` | Имя инструмента операции API (`search_issues`, `get_issue`, `issues_add_comment`; найти — `api_search`). |
| `args` | Фиксированные аргументы операции (TOML-таблица): параметры пути и запроса с именами из API и `body` целиком. Значения проверяются по схеме операции. |
| `jq` | [Фильтр ответа](#фильтр-ответа-jq), который применяется всегда. |

Фиксированные аргументы убираются из схемы инструмента: агент передаёт только остальные аргументы операции, а попытка передать фиксированный — ошибка. Нельзя фиксировать `save_to` и файловые аргументы (пути проверяются при каждом вызове), а также `null`. Кроме аргументов операции, пользовательский инструмент принимает `jq`: фильтр из вызова применяется после фильтра из файла.

Уровень доступа и аннотации инструмента — как у его операции; инструменты выше уровня сервера не регистрируются, а вызов такого инструмента объясняет, как поднять уровень. Наборы инструментов (`--toolsets`) пользовательские инструменты не ограничивают; с `--dynamic-toolsets` они регистрируются сразу при запуске, без `enable_toolset`.

Ошибки в файле останавливают запуск сервера с понятным сообщением (файл и инструмент): неверный TOML, неизвестные поля, неизвестная операция или аргумент, неверный фильтр. Имя, совпадающее со встроенным инструментом (с любой операцией API, `api_request`, `api_search`, `list_toolsets`, `enable_toolset`, `disable_toolset`) или с другим пользовательским инструментом, — тоже ошибка запуска, а не тихий пропуск. Проверить файлы заранее можно командой [`tracker-mcp tools check`](cli.md#tools).

## Локальные файлы

Инструменты загрузки (`post_attachment`, `temp_attachment`, `import_attachments`) принимают в аргументе `file` путь к файлу, а инструменты, которые возвращают файл (`issues_get_attachment`, `get_attachment_preview`, `api_request` для таких операций), сохраняют его по пути из `save_to`. Пути должны быть внутри разрешённых каталогов: рабочего каталога сервера, системного временного каталога и каталогов `allow_path` профиля ([подробнее](security.md#локальные-файлы)). В [HTTP-режиме](http.md#отличия-от-stdio) эти инструменты не регистрируются.

## Инструкции сервера

При подключении сервер передаёт агенту инструкции: уровень доступа и включённые наборы, как найти выключенную операцию, как включать наборы (с `--dynamic-toolsets`), какие есть пользовательские инструменты, как работать с постраничной выдачей, большими ответами и фильтром `jq`, какие каталоги разрешены для файлов, что токен никогда не передаётся в аргументах и не запрашивается в чате и что делать при `401`. Отдельно сказано не переносить персональные данные из ответов в логи, коммиты и код без просьбы пользователя.
