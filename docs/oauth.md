# OAuth-приложение и токен

Tracker API принимает OAuth-токен Яндекса. Своего OAuth-приложения в `tracker-mcp` нет: токен выдаёт приложение, которое вы создаёте сами. Так права, срок жизни и отзыв токена полностью под вашим контролем, а в бинарнике нет чужого `ClientID`.

`connect` проводит через все шаги сам: открывает страницу создания приложения, подсказывает настройки, спрашивает `ClientID`, открывает ссылку получения токена и принимает токен скрытым вводом ([справочник `connect`](cli.md#connect)). Ниже — то же вручную и почему настройки именно такие.

Федеративные и сервисные аккаунты организации Yandex Cloud OAuth-токен не получают: для них — [IAM-токены через `yc`](iam.md).

## Создание приложения

1. Откройте <https://oauth.yandex.ru/client/new/> под аккаунтом, которому будет принадлежать приложение.
2. Тип — «Для доступа к API или отладки».
3. Название — любое, по которому приложение легко узнать и отозвать, например `tracker-mcp-codex`. Контактная почта — ваша.
4. Права:
   - «Чтение из трекера» (`tracker:read`) — всегда;
   - «Запись в трекер» (`tracker:write`) — только если агенту нужна запись (уровень записи или удаления в профиле: `connect --allow-write`, `--allow-destructive` или `tracker-mcp ui`).
5. Если форма спрашивает Redirect URI (платформа «Веб-сервисы»), укажите `https://oauth.yandex.ru/verification_code`.
6. Сохраните приложение и скопируйте его `ClientID` (32 шестнадцатеричных символа). `ClientID` не секретный, Client secret не нужен.

`connect` сохраняет `ClientID` в профиль (`client_id` в `profiles.toml`), и при повторном запуске его больше не спрашивает. Передать его заранее можно флагом `--client-id`.

## Получение токена

Откройте ссылку авторизации приложения:

```text
https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>
```

Войдите в аккаунт, от имени которого будет работать агент, разрешите доступ и скопируйте показанный токен. Вставьте его в скрытый ввод `connect` или `auth login`: токен проверяется запросом `GET /v3/myself` и сохраняется в системное хранилище. Ни в конфигурацию клиента, ни в файлы, ни в переменные окружения он не попадает.

Агент работает с правами пользователя токена: Tracker покажет ему только те очереди и задачи, которые видит этот пользователь, а изменения будут сделаны от его имени. Если агентам не нужен доступ ко всему, что видите вы, заведите для них отдельного пользователя организации с нужными правами в Tracker и получайте токен под ним.

Токену нужна [организация](cli.md#профили): ID организации Yandex 360 для бизнеса (`X-Org-ID`) или Yandex Cloud Organization (`X-Cloud-Org-ID`). Её спрашивают `connect` и `auth login`.

## Права приложения

Права токена — это права приложения на момент получения токена. Сервер тоже ограничивает агента (по умолчанию только чтение), но это ограничение программы, а не токена:

- **Сервер только на чтение не делает токен безопасным.** Токен с `tracker:write` позволяет менять данные любым способом: если он утечёт (из логов, из буфера обмена, через агента с доступом к оболочке, из конфигурации HTTP-клиента), им можно писать в обход сервера. Токен только с `tracker:read` при утечке позволяет только читать.
- **В HTTP-режиме токен виден агенту** в конфигурации клиента, поэтому там права токена — единственная настоящая граница ([модель угроз](http.md#модель-угроз)).

Поэтому агенту, которому достаточно чтения, давайте токен приложения только с `tracker:read`, а `tracker:write` добавляйте только тем, кто действительно создаёт и меняет задачи.

Чтобы расширить права (например, включить запись для агента, который раньше только читал), добавьте приложению право «Запись в трекер» на <https://oauth.yandex.ru/> и получите новый токен: у уже выданного токена остаются прежние права. Затем сохраните его: `tracker-mcp connect <клиент> --allow-write` или `tracker-mcp auth login --profile <профиль>` и поднимите уровень профиля в `tracker-mcp ui`.

## Приложение на каждого агента

Создавайте отдельное приложение и токен для каждого клиента (Claude Code, Codex, CI, HTTP-сервер для команды) и храните их в отдельных профилях:

- токен любого агента можно отозвать, не затрагивая остальных;
- права настраиваются под каждого: одному только чтение, другому запись;
- в списке приложений с доступом к аккаунту сразу видно, какое из них какому агенту принадлежит.

`connect` по умолчанию создаёт профиль с именем клиента (`claude-code`, `codex`) и предлагает назвать приложение `tracker-mcp-<профиль>`.

## Отзыв токена

- Удалите токен из хранилища: `tracker-mcp auth logout --profile <профиль>` (с `--forget` — и настройки профиля).
- Отзовите сам токен: отзовите доступ приложения в настройках Яндекс ID (список приложений, у которых есть доступ к аккаунту) или удалите приложение на <https://oauth.yandex.ru/>. Удаление из хранилища не отзывает токен: если он мог утечь, отзывайте обязательно.

Когда токен истечёт или будет отозван, Tracker ответит `401`, а агент предложит выполнить `tracker-mcp auth login --profile <профиль>`.
