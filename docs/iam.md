# IAM-токены: федеративные и сервисные аккаунты

Обычный пользователь работает с Tracker через [OAuth-токен](oauth.md). Федеративные аккаунты (вход через SSO организации Yandex Cloud) и сервисные аккаунты Yandex Cloud OAuth-токен Яндекса не получают: Tracker принимает от них IAM-токен Yandex Cloud в заголовке `Authorization: Bearer <IAM-токен>`.

IAM-токен живёт не больше 12 часов, поэтому `tracker-mcp` его не хранит: в профиле записано только, что профиль работает с IAM, и как получить токен. Сервер получает токен командой `yc iam create-token` и держит его только в памяти процесса.

## Когда нужен IAM

- **Федеративный аккаунт** — пользователь входит в организацию Yandex Cloud через SSO своей компании (федерация удостоверений) и не имеет аккаунта Яндекс ID для OAuth.
- **Сервисный аккаунт** — робот без человека: CI, автоматизация, общий агент. Сервисный аккаунт Yandex Cloud подключают к Tracker через поддержку Tracker; после этого он работает с Tracker как отдельный пользователь со своими правами.

IAM работает только с организацией Yandex Cloud (заголовок `X-Cloud-Org-ID`). Профиль с IAM и организацией Yandex 360 (`X-Org-ID`) не запускается.

## Настройка `yc`

Нужен [Yandex Cloud CLI](https://yandex.cloud/ru/docs/cli/quickstart) (`yc`). `tracker-mcp` ищет его в `PATH` или берёт абсолютный путь из `--yc-path`. Учётные данные остаются в конфигурации `yc` (`~/.config/yandex-cloud`), `tracker-mcp` их не читает и не копирует.

Федеративный аккаунт:

```bash
yc init --federation-id <ID федерации>
yc iam create-token        # проверка: печатает токен, при первом запуске откроет браузер для входа
```

Сервисный аккаунт (отдельный профиль `yc`, ключ сервисного аккаунта):

```bash
yc iam key create --service-account-name <имя> --output ~/.config/yandex-cloud/tracker-sa-key.json
yc config profile create tracker-sa
yc config set service-account-key ~/.config/yandex-cloud/tracker-sa-key.json
yc iam create-token --profile tracker-sa
```

Ключ сервисного аккаунта — долгоживущий секрет: держите файл с правами `600` вне репозиториев и каталогов, к которым есть доступ у агента, и отзывайте ключ, если он мог утечь.

Если команда `yc iam create-token` (с `--profile`, если нужен) печатает токен, `tracker-mcp` сможет его получить. Сам токен никуда не копируйте.

## Подключение

Профиль с IAM настраивают `auth login` или `connect`:

```bash
tracker-mcp auth login --profile fed --auth iam --cloud-org-id <ID организации> [--yc-profile <профиль yc>] [--yc-path <путь к yc>]
tracker-mcp connect codex --iam --cloud-org-id <ID организации> [--yc-profile <профиль yc>]
```

Команда сохраняет в `profiles.toml` тип авторизации, организацию и настройки `yc`, получает токен через `yc` и проверяет его запросом `GET /v3/myself`; печатается логин пользователя. Если `yc` или проверка не прошли, ничего не сохраняется. `--skip-check` сохраняет профиль без запуска `yc` и без запроса к API. Для федеративного аккаунта `yc` может открыть браузер для входа: команда ждёт его до трёх минут.

```toml
[profiles.fed]
auth = "iam"
yc_profile = "tracker-sa"     # необязательно: без него — активный профиль yc
yc_path = "/opt/yc/bin/yc"    # необязательно: без него — yc из PATH

[profiles.fed.org]
type = "cloud"
id = "<ID организации>"
```

Повторные `auth login` и `connect` для такого профиля остаются на IAM и без флага. Вернуть профиль на OAuth: `tracker-mcp auth login --profile <профиль> --auth oauth`.

`auth status` и `serve --status` показывают тип авторизации и команду `yc`; `auth status` вдобавок получает токен и показывает пользователя (`--skip-check` — без `yc` и без запроса). Системное хранилище профилю с IAM не нужно: такой профиль работает и на Linux-сервере без Secret Service.

## Как сервер обновляет токен

- Токен запрашивается у `yc` перед первым запросом к API и заменяется не реже раза в час, а если `yc` сообщил срок (`expires_at`), то и за 10 минут до его истечения. Сервер работает сколько угодно дольше 12 часов без перезапуска.
- Если Tracker ответил `401`, сервер один раз получает у `yc` новый токен и повторяет запрос. Если `yc` выдал тот же токен, повтора нет: дело не в сроке. Запросы `POST` и `PATCH` повторяются, только если `401` пришёл на сам запрос, а не после редиректа: `401` Tracker возвращает до выполнения операции, поэтому повтор не создаст задачу или комментарий дважды.
- Одновременно работает не больше одного `yc`: остальные запросы ждут и получают тот же токен.
- `yc` запускается без оболочки, со списком аргументов `iam create-token [--profile <профиль>] --format json`, закрытым stdin и таймаутом 60 секунд; по таймауту процесс останавливается.

## Ограничения

- Нужен работающий `yc` на машине, где запущен сервер. Если `yc` не найден, упал или не ответил вовремя, запрос к API не отправляется, а агент получает ошибку с командой `yc`, которую нужно проверить.
- Токен не переживает перезапуск сервера: после запуска он снова запрашивается у `yc`.
- `yc` берёт учётные данные из своей конфигурации и переменных окружения. Их защита — на стороне `yc` и пользователя.
- В [HTTP-режиме](http.md) сервер IAM-токены не получает и не обновляет: агент сам передаёт `Authorization: Bearer <IAM-токен>` в каждом запросе, а когда токен истечёт, Tracker ответит `401`.

Ошибки `yc` и `401` с IAM разобраны в [решении проблем](troubleshooting.md#iam-yc-не-выдаёт-токен).
